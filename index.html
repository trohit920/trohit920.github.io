Uncertainty Quantification for LLMs

PYTORCH · HUGGING FACE · OPEN SOURCE

Token- and sentence-level uncertainty for a local Qwen2.5-1.5B: predictive entropy, perplexity, max-softmax, and semantic entropy via NLI meaning-clustering — benchmarked on factual QA and math.

0.945AUROC from one free forward pass
0.900AUROC from 10-sample semantic entropy
71%of the compute, for 80% of the gain
  • Error-detection AUROC, ECE with reliability diagrams, risk-coverage curves, bootstrap CIs — all hand-implemented and unit-tested.
  • The free signal beat the expensive one, and I traced why rather than shrugging: question-conditioned NLI collapses on comparative questions, so meaning-clustering merges answers that genuinely differ.
  • An uncertainty-gated cascade spends the sampling budget only where the model is actually unsure, instead of uniformly across every prompt.

CabinSense — In-Cabin Driver & Occupant Monitoring

ONNX RUNTIME · MOBILENETV3 · EDGE / SoC

Real-time DMS/OMS inferring eleven signals — drowsiness, distraction, gaze zone, yawning, phone use, drinking, smoking, seatbelt, glasses, cap, and occupant count — from a single camera feed.

11signals from one camera feed
7.4 msper frame on CPU, ~135 FPS
6–10×slower under INT8, not faster
  • Fuses ONNX face detection, 98-point landmarks, 6DRepNet head pose, L2CS gaze, EAR/MAR/PERCLOS geometry, and localized YOLO detectors into one temporally-smoothed state.
  • Found the phone classifier firing at p90 ≈ 0.99 on a clip containing no phone — a whole-image head has no concept of absence. Moved object-like classes to localized detectors, keeping classifiers only for genuine face attributes and geometry for yawn.
  • INT8 turned out to be a size win and a speed loss — dequantization overhead swamps a MobileNetV3's tiny convolutions. So fp32 ships where compute is the constraint and INT8 only where flash and RAM are, with the benchmark script in the repo instead of a claim.
  • Driver-ROI scheduling runs detectors on ~half the pixels (141/145 frames ROI-only) with periodic full-frame sweeps to recount occupants; one consolidated YOLOv8n covers three classes in a single inference to keep the SoC budget flat.

Agentic RAG with Guardrails

LANGGRAPH · FASTAPI · FULLY LOCAL

A local agentic RAG assistant over enterprise documents where refusing is a first-class outcome — and a harness that measures whether it refuses correctly.

1.00faithfulness — every answer entailed
0.94abstention accuracy, up from 0.69
0access-control retrieval leaks
  • Clearance is enforced inside the vector-store filter, not the prompt, so protected text never enters the model's context at all. That is the difference between a policy and a guardrail — and the one that survives an audit.
  • Pure NLI over-abstained on valid paraphrases; an embedding-cosine rescue fixed it with faithfulness held at 1.00. NLI catches contradictions, cosine rescues restatements. Sentence-level premises moved entailment on a grounded pair from 0.0003 to 0.988.
  • Hybrid retrieval (dense + BM25 via RRF), prompt-injection defense, and document-level access control.
  • Judge-free retrieval and answer-quality harness — hit@k, MRR, nDCG, NLI faithfulness — plus a two-model accuracy/latency/cost comparison.

StreamRec — Two-Stage Recommender & Hybrid Search

PYTORCH · LIGHTGBM · FASTAPI · FULLY LOCAL

The streaming content-discovery stack end to end on MovieLens-1M — candidate generation, learning-to-rank, bandit re-ranking, cold start, and search — built to find out which stage the wins actually come from.

2.3×NDCG@10 over the popularity baseline
+12%more NDCG@10 from the ranker
67×the latency that ranker costs
  • Retrieval does the heavy lifting, and it also widens the catalogue: coverage goes 0.08 → 0.74 of all titles. A logQ correction on the in-batch negatives — which otherwise punish popular items for being popular — more than doubled Recall@10 (0.033 → 0.085).
  • The ranker's 12% costs 7.3 ms: retrieval alone answers in 0.11 ms p50, the full two-stage request in 7.4 ms. That trade is the actual engineering decision — worth paying on a homepage, not on typeahead.
  • The ranker's strongest feature by gain was neither popularity nor any embedding score — it was how many retrievers independently surfaced the same item. LinUCB, meanwhile, tied the greedy ranker on offline replay (0.387 vs 0.388): a bandit cannot prove itself against a static log, so it ships behind the replay estimator rather than a chart pretending otherwise.
  • Cold start via bge content embeddings (a brand-new title is retrievable with zero interactions), hybrid dense + BM25 search fused by RRF (28 ms p50), MMR diversity (intra-list similarity 0.45 → 0.41), PSI drift monitoring, and FastAPI serving — with Spark/Airflow/Kubernetes scale-out documented rather than stubbed.
